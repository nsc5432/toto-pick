# 통계 기반 수익 모델 설계서

목적: `research` 탐색 파이프라인에 태울 **통계학적 근거가 있는 알고리즘 후보**를 정의한다.
이 문서는 설계서다 — 구현은 후보별로 별도 요청 시 진행하고, 구현 전에는 반드시
[MCP SQL 사전 검증](#3-sql-사전-검증--구현-전-필수-관문)을 통과해야 한다.

목표(`application.yaml > research.goal`, 요청별 변경 불가):

| 기준 | 값 | 의미 |
|---|---|---|
| 검증 수익률 | ≥ +10% | (output−input)/input, **검증 구간만** |
| 최소 조합 수 | ≥ 100 | 미만이면 운 — 실격 |
| 최소 베팅일 | ≥ 20 | 특정 기간 몰빵 방지 |

## 1. 현황 진단 — 원장이 말해주는 것

`research/experiments.jsonl` 14건 전원 미달성. 대표 실패 패턴(MARKET_EDGE):

- `combinedN=4~5` 스윕 → 학습 적중률 ~1%, 검증 적중 **0건**, 검증 수익률 −100%
- 학습에서 +4~6%가 나온 후보도 검증에서 전멸 → 전형적인 **소표본 행운 + 과최적화**

### 왜 combinedN이 크면 구조적으로 지는가 (파룰레이 수학)

경기 하나의 배당에는 하우스 마진 m이 섞여 있다 (오버라운드 = 역배당 합 − 1, 통상 15~25%).
N경기 조합의 기대값은 다리마다 마진이 **곱으로 누적**된다:

```
EV(조합) ≈ (1 − m_유효)^N − 1        (모델 엣지가 0일 때)
m_유효 = 0.05 가정 시:  N=2 → −9.8%,  N=3 → −14.3%,  N=5 → −22.6%
```

즉 목표 +10%를 넘으려면 다리당 요구되는 엣지가 N에 따라 커진다. 동시에 적중 확률은
p^N으로 붕괴해 분산이 폭발하고, 100조합 표본으로는 참 수익률의 신뢰구간이 목표를 덮지 못한다.

> **설계 결정 D1**: 이후 모든 후보의 `combinedN` 탐색 범위는 **2~3**을 기본으로 한다.
> 4 이상은 다리당 엣지가 SQL로 입증된 경우에만 허용.

또 하나의 교훈: 현재 확률 추정이 "최근 N경기 승률 + 상수 스무딩"뿐이다. 승/패만 세는 승률은
정보량이 낮고 노이즈가 크다. **개선 지렛대는 (a) 확률 추정의 품질, (b) 조합 구성** 두 가지다.

## 2. 모델 후보 (우선순위 순)

각 후보: 가설 → 통계 근거 → 스키마 충족 여부 → 노브(ParamSpec) → 검증 방법.
계열 분류는 `.claude/skills/algo-search/references/taxonomy.md` 기준.

### M1. 피타고리안 기대승률 × 시장 괴리 — 계열 C 변형 ★ 최우선

- **가설**: 득점/실점은 승패보다 정보량이 많다. 점수 기반 기대승률이 시장 확률과 괴리된 쪽이 +EV.
- **통계 근거**: Bill James 피타고리안 기대승률 — 야구에서 실제 승률보다 미래 승률을 더 잘 예측함이
  반복 검증된 고전적 결과. 승패는 1비트, 점수차는 연속 정보.

  ```
  W% = RS^k / (RS^k + RA^k)        RS=득점합, RA=실점합, k ≈ 1.8 (MLB 기준, KBO는 스윕으로 결정)
  ```
- **데이터**: `res1`/`res2`(스코어)가 `baseball_result`에 이미 있음 → **스키마 충족**.
- **구현 방향**: `MARKET_EDGE`의 폼 승률 부분만 피타고리안 추정으로 교체. de-vig 로직은 그대로 재사용.
  `TeamFormIndex`에 득실 집계를 추가하거나 별도 인덱스로 — 단, **날짜 인자를 받는 lookahead-safe
  구조는 동일하게 유지**.
- **노브**: `num`(집계 경기 수 15~45), `pythExponent`(1.5~2.2), `edgeThreshold`(0.03~0.15),
  `minOdds`(1.3~2.0), `combinedN`(2~3)
- **사전 검증 SQL**: 최근 N경기 득실비 상위 팀 vs 하위 팀의 이후 경기 실제 승률 차이가
  시장 내재 확률 차이보다 큰지 확인.

### M2. 수축 추정(Empirical Bayes) 폼 — 계열 B/C 공통 기반

- **가설**: 원시 `winPercent`는 표본 10~20경기짜리 노이즈다. 리그 평균으로 수축(shrink)하면
  추정이 안정되어 같은 알고리즘도 성능이 오른다.
- **통계 근거**: Beta-Binomial 수축 — 소표본 비율 추정의 표준 처방. 현재 `FORM_SMOOTHING=5.0`
  상수가 이것의 조악한 형태인데, 수축 강도가 근거 없이 고정돼 있고 스윕도 안 된다
  (→ CLAUDE.md의 "상수는 검증되지 않는다" 규칙 위반 상태).

  ```
  p̂ = (승수 + α) / (경기수 + α + β)      α/(α+β) = 리그 평균 승률, α+β = 수축 강도(노브)
  ```
- **데이터**: 추가 데이터 불필요 → **스키마 충족**.
- **구현 방향**: 단독 알고리즘이 아니라 **M1/기존 MARKET_EDGE의 확률 추정 개선**으로 적용.
  `shrinkStrength`를 ParamSpec으로 승격해 스윕이 최적 수축 강도를 고르게 한다.
- **노브**: `shrinkStrength`(2~30)

### M3. 배당 구조 신호 — 계열 E (미개척)

- **가설**: 배당의 **모양** 자체가 정보다. 특히 ① 오버라운드가 작은 경기 = 북메이커가 확신하는
  경기 → 페이버릿 추종 성공률↑, ② favorite–longshot bias — 저배당이 내재 확률 대비 저평가되는
  경향은 베팅 시장 문헌에서 가장 재현성 높은 편향.
- **통계 근거**: 배당 구간별 (실제 적중률 − de-vig 내재 확률)을 비교하는 **캘리브레이션 분석**.
  양(+)인 구간이 있으면 그 구간만 베팅하는 것이 곧 전략이 된다.
- **데이터**: `homeDiv/drawDiv/awayDiv`만 사용, 폼 히스토리 불필요 → **스키마 충족**,
  시즌 초에도 작동한다는 부가 장점.
- **구현 방향**: 신규 `ODDS_STRUCTURE` 알고리즘. de-vig 후 내재 확률이 특정 구간에 들고
  오버라운드가 임계 이하인 경기의 페이버릿(또는 SQL이 지목한 구간)만 선택.
- **노브**: `probLow`/`probHigh`(선택 구간), `maxOverround`, `combinedN`(2~3)
- **사전 검증 SQL** (이 계열은 SQL 결과가 곧 전략 — 반드시 먼저 실행):

  ```sql
  -- 내재 확률 십분위별 캘리브레이션: actual_rate > implied 인 구간이 엣지
  SELECT FLOOR(implied_home * 10) AS bucket,
         COUNT(*) AS n,
         AVG(implied_home) AS implied,
         AVG(CASE WHEN res1 > res2 THEN 1 ELSE 0 END) AS actual_rate
  FROM (
    SELECT res1, res2,
           (1/homeDiv) / (1/homeDiv + 1/drawDiv + 1/awayDiv) AS implied_home
    FROM baseball_result
    WHERE homeDiv IS NOT NULL AND drawDiv IS NOT NULL AND awayDiv IS NOT NULL
  ) t
  GROUP BY bucket ORDER BY bucket;
  ```

### M4. Elo / Bradley–Terry 레이팅 — 계열 C 고급 변형

- **가설**: 경기 단위로 갱신되는 레이팅은 "최근 N경기 승률"보다 상대 전력·최신성을 정교하게 반영한다.
- **통계 근거**: Elo는 Bradley–Terry 모델의 온라인 근사. 홈 어드밴티지를 상수 H로 자연스럽게 흡수:

  ```
  P(홈승) = 1 / (1 + 10^(−(R_home + H − R_away)/400))
  갱신:  R ← R + K·(결과 − 기대)
  ```
- **데이터**: 승패(+점수차로 K 보정 가능) → **스키마 충족**.
- **구현 방향**: `TeamFormIndex`처럼 **런당 1회, 날짜순으로 구축**하는 레이팅 인덱스
  (날짜 인자로 조회해 lookahead 차단 — 기존 패턴 그대로). 확률을 M1과 같은 괴리 비교에 투입.
- **노브**: `kFactor`(8~40), `homeAdvantage`(0~100 Elo점), `edgeThreshold`, `combinedN`(2~3)
- **주의**: 구현 비용이 가장 크다. M1이 실패한 뒤에 착수.

### M5. 조합 구성 개선 — 계열 F (신호 계열과 반드시 짝지어 평가)

- **가설**: 같은 신호라도 묶는 법이 수익률을 바꾼다. 현재 "정렬 후 N개씩 자르고 나머지 버림"은
  약한 신호끼리 한 조합에 몰리는 구조.
- **후보**: ① `combinedN=2` 고정 + 강신호만, ② 조합 배당곱이 목표 구간(예 2.5~5.0)에 들도록 greedy
  구성, ③ 최강 신호 1개 + 저배당 안정 다리 1개 혼합.
- **평가 규칙**: 단독 계열이 아니므로 M1 또는 M3에 얹어 **동일 신호·다른 구성**으로 A/B 비교.

### M6. 일정·맥락 신호 — 계열 D (보류)

휴식일 간격·연속 원정은 `ymd`/`tm`에서 파생 가능하지만, 효과 크기가 작아 마진(15%+)을 단독으로
넘기 어렵다는 것이 야구 문헌의 일반적 결과. **M1~M3의 보조 필터**로만 검토. 구장·선발투수는
현재 스키마로 불가 — 설계 금지.

## 3. SQL 사전 검증 — 구현 전 필수 관문

`kbo-mysql` MCP(읽기 전용)로 다음을 순서대로 확인한 뒤에만 구현에 착수한다.
**SQL에서 안 보이는 신호는 스윕에서도 안 나온다** — 구현·스윕 비용이 훨씬 비싸다.

1. **마진 실측**: `AVG(1/homeDiv + 1/drawDiv + 1/awayDiv) − 1` — 넘어야 할 허들의 실제 크기.
2. **캘리브레이션 테이블** (M3 쿼리): 십분위별 `actual − implied`. 여기서 +2%p 이상 나는 구간이
   없으면 C/E 계열 전체의 기대치를 낮춰 잡아야 한다.
3. **후보별 신호 존재 확인**: 예) M1 — 최근 20경기 득실비 상위/하위 팀의 이후 승률 스프레드가
   시장 스프레드보다 큰가.
4. **표본 수 확인**: 필터 통과 경기 수 × 기간으로 조합 100개·베팅일 20일이 나오는지 역산.
   여기서 미달이면 필터를 완화하거나 후보를 버린다 (스윕 후 "표본 부족" 진단의 사전 차단).

주의: SQL 검증도 **학습 구간(YMD 기준 앞 70%)만** 대상으로 한다. 전체 기간으로 신호를 찾으면
그 자체가 검증 구간 누수다.

## 4. 통계적 검증 규율

파이프라인이 이미 강제하는 것(학습/검증 분리, 최소 표본 게이트, 시드 고정, 원장 기록) 위에
사람이 지켜야 할 것:

- **다중 비교 문제**: 후보 200개를 스윕하면 우연히 좋아 보이는 것이 반드시 나온다. 격자는
  노브당 3~5단계로 작게, 검증 재측정은 top-K(5)만 — 파이프라인 기본값을 넓히지 말 것.
- **검증 숫자로 파라미터를 고르지 않는다** — 재탐색 사유는 오직 학습 진단(표본 부족 등).
- **재시드 금지**: seed=42 고정. 시드를 바꿔 다시 돌리는 것은 p-hacking이다.
- **분산 감각**: 조합 100개·평균 배당 3.0이면 수익률 표준편차가 ±15%p를 넘는다.
  검증 +10%는 "달성"이지 "증명"이 아니다 — 원장에 축적해 재현성으로 판단한다.
- 보고는 항상 **검증 지표**로. 학습 지표 보고는 anti-pattern (`algo-search` SKILL 참조).

## 5. 구현 시 공통 규칙 (CLAUDE.md 요약 + 이 문서의 결정)

- `TunableAlgorithm` 구현 — **모든 임계값·상수는 `paramSpace()`에 선언** (M2의 수축 강도 포함).
- 팀 폼·레이팅은 `input.formIndex()` 패턴 — 날짜 인자를 받는 인덱스를 런당 1회 구축, `historyGames` 직접 순회 금지.
- 순수 로직이면 `pick/domain/` + `PickAlgorithmConfig` `@Bean`, 데이터 의존이면 `pick/infrastructure/algorithm/` `@Component`.
- `code()`는 영구 식별자 — 한 번 원장/DB에 남으면 개명 금지.
- `combinedN` 기본 탐색 범위 2~3 (설계 결정 D1).
- 승자 확정 후에만 `POST /api/picks/simulate`로 운영 테이블 기록.

## 7. 관문 1·2 실행 결과 (2026-08-16)

유니버스: `야구 승1패` × KBO/NPB/MLB. 전체 2,614경기 중 3면 배당 보유 2,572경기, 116일
(260421~260815). 학습 컷 = `round(116 × 0.7) = 81`번째 일자 → **`YMD ≤ 260711`, 1,860경기**
(`BacktestSplit.byRatio`와 동일 기준). 모든 수치는 학습 구간만 사용.

### 관문 1 — 마진: 유효 마진 12~15% 실재, 단 저장 컬럼으로는 "측정" 불가

- 저장 컬럼 오버라운드: **전 행 정확히 15.0%** (min 14.80, max 15.18). 이것은 측정값이 아니라
  `BaseballResultDivBackfillService`의 가정(1.15)이 되돌아온 것 — 3면 배당은 실현 결과의
  배당(`TOTAL_DIV`)만 실측이고 나머지 두 면은 승패 마켓 비율로 역산한 **추정치**다.
- 독립 실측 (실측 `TOTAL_DIV`만 사용, 결과별 무차별 베팅 ROI): 승 **−15.5%**, 1 **−11.7%**,
  패 **−12.3%**. → 넘어야 할 다리당 허들은 설계 가정대로 실재하며, 실측 배당 기준으로
  양(+)인 무차별 구간은 없다.

### 관문 2 — 캘리브레이션: +구간은 발견됐으나 전부 아티팩트 판정

십분위 테이블(홈/무/원정 3방향)에서 `actual − implied ≥ +2%p` 구간이 다수 나왔다
(홈 implied 0.2~0.3 구간: gap +27%p, ROI +75.8% / 원정 0.4~0.5: +24.6%p / 원정 0.5+:
+41.7%p, 적중률 95%). **그러나 이는 시장 신호가 아니라 백필 배당의 차등 측정 편향이다.** 근거:

1. 실현된 면만 실측 배당이고 비실현 면은 추정치 → 십분위 **소속 자체가 결과와 상관**된다
   (예: 홈 승리 행의 `HOME_DIV`는 실측 3면 배당이라 낮은 내재확률 구간에 몰리고, 홈 패배 행의
   `HOME_DIV`는 추정치라 중간 구간에 몰림 → 낮은 구간의 적중률이 기계적으로 부풀려짐).
2. 결과별 평균 내재확률이 평탄/역전: `avg(implied_home)` = 승 0.376 / 1 0.380 / 패 0.387.
   실제 시장이라면 이긴 쪽의 사전 확률이 유의하게 높아야 한다 — 저장된 홈 내재확률은
   판별력이 사실상 0이다.
3. 원정 0.5+ 구간 적중률 95%(n=40), 무배당 최저 구간 적중 0/130 같은 수치는 실제 북메이커
   시장에서 존재할 수 없다.

참고 — 결과 의미 실증: `승` = 홈 2점차+ 승, `패` = 원정 2점차+ 승, `1` = 1점차 경기(동점 16건 포함).

### 판정 및 설계 결정 D2

- **2단계 M3(배당 구조): 부결.** 배당의 "모양"을 읽는 계열인데 모양 자체가 합성이다 —
  오버라운드가 전 행 1.15 고정이라 `maxOverround` 노브는 죽어 있고, `probLow/probHigh`
  구간 선택은 위 아티팩트를 그대로 줍는다. 표본 역산(§3-4)은 부결로 생략.
- **설계 결정 D2**: `HOME_DIV/DRAW_DIV/AWAY_DIV`를 **선택 신호**로 읽는 알고리즘의 백테스트
  수치는 신뢰할 수 없다 (선택은 추정 배당, 정산은 실측 배당 → 방향 의존 편향; 예컨대 원정
  고내재확률 추종은 가짜 +35~55% ROI가 나온다). 이후 탐색이 이런 후보에서 목표 달성을
  보고하면 **아티팩트 수확을 먼저 의심**할 것. 해제 조건: 원시(발표된) 3면 배당 데이터 확보.
- **M1 함의**: 시장 괴리(edge) 계산이 같은 컬럼을 읽으므로 동일하게 오염된다. 3단계는
  "피타고리안 − 시장 내재확률 괴리"가 아니라 **폼/점수 기반 신호로만 선택하고 배당은
  정산에만 쓰는** 변형(순수 피타고리안 랭킹 + 저노출 배당 필터 최소화)으로 재설계해야 한다.
  정산은 항상 실현 면의 실측 배당으로 이루어지므로, 선택이 배당 컬럼과 독립이면 백테스트는
  편향되지 않는다.

## 8. M1(D2 재설계) 사전 검증 결과 (2026-08-16) — 부결

D2 제약을 반영한 M1 변형(피타고리안 폼으로만 선택, 배당은 실측 `TOTAL_DIV` 정산에만 사용,
계열 재분류: C→B 득실 기반 랭킹)을 §3 관문에 따라 구현 전에 데이터로 검증했다.
학습 구간(`YMD ≤ 260711`)만 사용, 중복 키(COND)는 최소 id 유지.

검증 방식: 팀별 직전 N경기 득실합으로 피타고리안 기대승률(RS^k/(RS^k+RA^k))을 계산하고,
홈−원정 갭 구간별로 우세측(갭>0→승, <0→패) 베팅의 적중률·ROI를 측정.
`num ∈ {10,20,30}`, `k ∈ {1.8, 2.1}`, 수축(shrink 10) 포함 — M2 수축도 함께 판정됨.

| 검증 항목 | 결과 |
|---|---|
| 갭↑ → 우세측 적중률↑ (단조성) | **없음** — 전 구간 34~43%에서 평평, 갭 최대 구간이 최소 구간과 동급 |
| 우세측 베팅 ROI | **전 구간·전 파라미터 음수** (−2.4% ~ −27%, 대부분 마진 수준 −8~−22%) |
| 역베팅(열세측) 변형 | 전부 음수 (−13% ~ −26%) |
| 접전(갭<0.03) → 1점차('1') 베팅 변형 | 최고 +1.1% (n=126) 단일 셀, 이웃 구간 전부 음수 — 노이즈 |

목표 역산: `combinedN=2`로 검증 +10%를 내려면 다리당 약 +4.9%가 필요한데, 관측된 다리당
ROI는 최선의 셀도 +1.1%(노이즈)다. 격차가 자릿수 수준이라 스윕으로 메울 수 없다.

**판정: 구현·스윕 없이 부결.** (`algo-search` 규칙 — "데이터에 신호의 흔적조차 없으면
구현하지 않는다". 원장은 탐색 파이프라인 전용이므로 이 부결은 원장이 아니라 여기 기록한다.)

### 확보 방법

**게시된 3면 배당**을 수집했다. 회차 목록 엔드포인트(`/util/gameinfo/get_proto_list.htm`)는

핸디캡·언더오버·홀짝·전반 마켓은 제외, 취소 경기(1.00/1.00/1.00)는 버렸다.

### 검증 — 조인과 교차검증

| 항목 | 결과 |

- **관문 1 — 마진**: 평균 오버라운드 **+15.29%** (중앙 15.0%, 범위 14.77~16.42%).
  백필의 1.15 가정은 평균적으로는 맞았다. 다만 **분산이 거의 없다**(전 행이 0.15 버킷).
- **관문 2 — 캘리브레이션**: 홈/무/원정 3방향 십분위 전부에서 `actual − implied`가 ±3%p 이내로

  0.2~0.3 구간(n=419, gap +2.1%p, ROI **−6.6%**) — 갭은 +2%p를 넘지만 마진을 못 넘는다.

  원정승 0.345로 **단조**. 원정 쪽도 대칭으로 0.355 < 0.366 < 0.382. 이제 배당이 결과를
  실제로 예측한다 — §7의 역전 현상은 백필 아티팩트였음이 확정됐다.

### 판정

- **설계 결정 D2 해제.** 단, 해제 조건은 "`PUB_*` 컬럼을 쓸 것"이다. 기존 `*_DIV` 컬럼을 선택
  신호로 읽는 코드는 여전히 오염돼 있다 — **알고리즘·백테스트가 `PUB_*`를 읽도록 바꾸기 전까지

- **C 계열(가치·괴리) 재개 가능.** §7에서 "신호 자체가 오염"이라 판정 불가였던 것이 이제
  측정 가능해졌다. 다만 관문 2가 말하는 것은 **배당 자체는 잘 캘리브레이션돼 있다**는 것이므로,

- **E 계열(배당 구조)은 여전히 부결.** 오버라운드가 14.8~16.4%로 사실상 상수여서

## 10. `PUB_*` 배선 + C 계열 재탐색 (2026-08-16) — 목표 게이트는 통과, **감사에서 부결**

### 배선 (D2 완전 해제)

배당을 읽는 유일한 통로를 `BaseballResult.publishedOdds()` → `ThreeWayOdds`로 만들었다.
`formIndex()`가 미래 참조를 구조적으로 막는 것과 같은 방식이다 — 각 알고리즘 작성자가 "발표
배당만 쓴다"를 기억하는 규칙이 아니라, 그 통로 말고는 배당을 얻을 방법이 없게 했다.
**백필 컬럼으로의 폴백은 의도적으로 없다.** 폴백이 있으면 D2가 조용히 되살아난다.

| 대상 | 변경 |
|---|---|
| `ThreeWayOdds` (신규) | de-vig 1곳으로 통합 — `overround()`, `impliedHome/Draw/Away()`, `impliedDecisive()` |
| `BaseballResult` | `pubHomeDiv/pubDrawDiv/pubAwayDiv` + `publishedOdds()`. 백필 3컬럼은 javadoc에 "선택 신호 금지" 명시 |
| JPA 엔티티·어댑터·응답 DTO | `PUB_*` 3컬럼 매핑 |
| `FAVORITE`·`WIN_RATE_ODDS`·`MARKET_EDGE` | 선택 시 `publishedOdds()`만 사용, 없으면 해당 경기 스킵 |
| `MARKET_EDGE` | `FORM_SMOOTHING = 5.0` 상수 → `shrinkStrength` `ParamSpec` (M2 수축 승격, 0~45) |
| 세 알고리즘 전부 | `combinedN` 탐색 범위 2~3으로 축소 (설계 결정 D1을 코드에 반영) |

정산(`PickSettlement`)은 바꿀 필요가 없었다. `TOTAL_DIV`는 실현면의 실측 배당이고 §9에서 그것이
발표 배당과 100% 일치함을 확인했으므로, **선택과 정산이 이미 같은 시장을 인용한다.**

`MARKET_EDGE` 격자는 4×2×5×3×4 = **480점(전수)**. 예산 480으로 실행해 랜덤 샘플링을 피했다.

|---|---|---|---|---|
| `MARKET_EDGE` | `combinedN=2, edgeThreshold=0.05, minOdds=1.4, num=30, shrinkStrength=0` | −25.4% | **+33.2%** | 163 |
| `MARKET_EDGE` | `edgeThreshold=0.02, minOdds=1.4, num=30, shrinkStrength=0` | −23.7% | +20.0% | 268 |
| `WIN_RATE_ODDS` | `combinedN=2, num=15, x=2.2, y=2.9` | −5.9% | −0.7% | 122 |
| `FAVORITE` (기준선) | `combinedN=3` | −29.8% | −22.2% | 223 |

파이프라인 판정은 `goalAchieved = true`였다. **그대로 보고하지 않았다** — §7이 남긴 규칙이
"목표 달성 보고 시 아티팩트 수확을 먼저 의심하라"이고, 학습 −25.4% → 검증 +33.2%의 58%p 순방향
격차는 그 자체로 경보다. 파라미터가 선택된 구간에서 25% 잃은 설정이 검증에서 33% 벌었다면,
선택이 옳았다는 뜻이 아니라 **검증 구간이 그 계열에 유리했다**는 뜻일 수 있다.

### 목표 게이트의 구조적 결함 → 안정성 관문 도입

`ExperimentGoal`은 검증 구간의 **합계**만 봤다. 그래서 마지막 2주의 고배당 연속 적중 하나로
게이트를 통과할 수 있었고, 실제로 통과했다. 목표치를 낮추는 것이 아니라 **조이는** 변경이므로
곧바로 반영했다 (`research.goal.max-train-validation-gap: 0.45`).

- **`maxTrainValidationGap`** — `|학습 − 검증|` 수익률 상한. 두 구간이 크게 어긋나면 엣지가 아니라
  꼬리의 운이다. 임계 0.45의 근거: 검증 163조합·학습 469조합, 평균 당첨배당 7.7·적중률 12%에서
  수익률 차이의 표준오차가 약 0.23이므로 **0.45 ≈ 2σ**. 이보다 좁히면 진짜 엣지도 걸러낸다.
- **`minProfitableSegments`** (선택, 기본 미설정) — 검증 구간을 4등분했을 때 수익 구간 수 하한.
  `BacktestMetrics`가 `segmentCount`/`profitableSegmentCount`를 항상 계산해 보고한다.

재판정 결과 — 문제의 후보는 이제 **부결**된다:

| 검사 | 기준 | 실측 | 판정 |
|---|---|---|---|
| 수익률 | ≥ 0.10 | 0.3315 | PASS |
| 최소 조합 수 | ≥ 100 | 163 | PASS |
| 최소 베팅일 수 | ≥ 20 | 43 | PASS |
| **학습·검증 격차** | **≤ 0.45** | **0.5854** | **FAIL** |

**중요한 부수 발견: 구간 분할 검사는 이 후보를 걸러내지 못한다.** 검증 구간(07/12~08/15) 내부만
4등분하면 **4/4 전부 수익**이기 때문이다 — §10 상단의 월별 감사에서 손실로 나온 구간들은 대부분
검증 구간 *이전*이었다. 반대로 학습 구간은 **0/4**다. 즉 "검증 구간 안에서의 안정성"은 이 위양성에
대해 무력했고, 실제로 일을 한 것은 **두 구간의 불일치**를 보는 검사다. 그래서 격차 검사만
기본 활성화하고 구간 검사는 선택으로 남겼다.

이것이 일반 교훈이다: 홀드아웃 구간 하나가 아무리 깨끗해 보여도, **학습 구간과 말이 맞지 않으면
그 구간이 특이했던 것**이다.

## 11. D 계열(일정·맥락) SQL 관문 (2026-08-16) — 부결

§8은 D 계열을 "효과 크기 < 마진"이라는 **문헌 근거만으로** 미구현 처리했다. 이제 발표 배당이
있으므로 실측할 수 있다 — 그리고 실측은 구현보다 훨씬 싸다.

먼저 `match_schedule`을 확인했다. **0행이고 추가 피처 컬럼도 없다** — 무료로 얻을 것은 없었다.
따라서 `baseball_result`만으로 파생 가능한 일정 피처를 대상으로 했다.

**측정 방식이 핵심이다: 적중률이 아니라 잔차를 본다.** 일정 정보는 북메이커도 아는 공개
정보이므로, 질문은 "휴식일이 승패를 예측하는가"가 아니라 "**배당이 이미 반영한 것 이상을**
예측하는가"다. 그래서 구간별 `실제 홈승률 − de-vig 내재 홈확률`을 본다. 시장이 완전히 반영하고
있으면 잔차는 모든 구간에서 0 근처다. 학습 구간(`YMD ≤ 260711`) 1,893경기.

| 피처 | 최선 구간 (n ≥ 300) | 잔차 | 홈베팅 ROI |
|---|---|---|---|
| 휴식일 차이(홈−원정) | `+0` (n=1,721) | −0.61%p | −14.4% |
| 홈팀 휴식일 | 2일 (n=324) | +5.05%p | **−2.7%** |
| 7일 경기수 차이 | −1 (n=313) | +4.14%p | **−1.5%** |
| 경기 시각 | 주간 (n=1,381) | −0.68%p | −14.6% |
| 리그 | NPB (n=360) | +3.99%p | **−1.0%** |

**표본이 유의미한 모든 구간의 ROI가 음수다.** 잔차가 +4~5%p로 보이는 구간들(홈휴식 2일,
저밀도, NPB)조차 손익분기에 못 미친다 — 마진 15.3%를 못 넘는다.

유의성도 없다. n=324에서 비율의 표준오차는 2.7%p이므로 +5.05%p는 **+1.9σ**이고, 이번 관문에서
비교한 구간은 약 35개다. 순전한 우연으로도 1.9σ급이 2개쯤 나오는 규모다.

부수 사실: 휴식일 차이는 **91%가 `+0`**(양 팀 모두 전날 경기)이다. 야구 일정 구조상 휴식일
비대칭 자체가 거의 발생하지 않아, 이 피처는 애초에 변별할 표본을 만들지 못한다.

## 12. 목표 재정의 — 시장 기대 대비 초과수익 (2026-08-16)

### 왜 절대 수익률이 목표로 부적절했나

절대 ROI는 **"돈을 벌었나"와 "정보가 있었나"를 한 숫자에 섞는다.** 마진 15.3% 시장에서 앞의
답은 거의 항상 '아니오'이고, 그건 뒤의 질문에 대해 아무것도 말해주지 않는다. 그런데 우리가
답을 구할 수 있는 질문은 뒤쪽이다.

기준선은 배당만으로 정확히 계산된다. de-vig 항등식상 어느 면을 고르든 한 다리의 기대수익은
`p_s × odds_s = 1/O` 로 **동일**하다(선택한 면과 무관). 실측 `O = 1.1529` → **−13.26%**.
학습 구간 실측이 이를 확인한다:

| | 값 |
|---|---|
| 이론 무기술 기대수익 `1/O − 1` | **−13.26%** |
| 홈 무조건 베팅 | −13.50% |
| 무(1점차) 무조건 베팅 | −10.79% |
| 원정 무조건 베팅 | −13.78% |

"기술 0"의 성적표가 사전에 정확히 정해져 있으므로, 그것을 빼고 남는 것이 곧 전략의 기여분이다.

### 세 번의 설계 수정 — 매번 같은 결함

목표를 초과수익으로 바꾼 뒤에도 파이프라인은 두 번 더 "달성"을 반환했고, 두 번 다 원인은
**표본 크기를 보지 않는 임계값**이었다.

1. **조합(슬립) 단위 → 다리(leg) 단위.** 첫 실행에서 `FAVORITE`가 3다리 **+12.0%**, 2다리
   **−14.3%**로 나왔다. 둘은 **같은 경기를 그대로 베팅하고 묶는 방식만 다르다.** 진짜 엣지는
   묶는 방식에 따라 부호가 뒤집힐 수 없다 — 3다리 조합의 분산이 너무 커서 100여 조합으로는
   신호가 묻혔을 뿐이다. 다리 단위는 표본이 2~3배이고, 조합 기준선이 다리 기준선의 곱이므로
   묶기의 영향이 **구조적으로 0**이다.
2. **고정 임계값 → t값.** 다리 300개면 노이즈만으로 ±7%p, 900개면 ±4%p다. 같은 +5%p가 표본에
   따라 전혀 다른 의미이므로 `min-excess-return`만으로는 관문이 될 수 없다. `t ≥ 2.0`을 함께
   걸었다 — 자주 베팅해 작은 엣지를 입증하든, 드물게 베팅해 큰 엣지를 보이든 둘 다 길이 열린다.
3. **절대 격차 → σ 격차.** 안정성 관문도 같은 결함이 있었다. `max-train-validation-gap: 0.17`은
   §10 후보의 표준오차 기준 2σ였는데, 표준오차가 더 작은 다른 후보에게는 2.2σ여서 **통과해버렸다**
   (격차 0.1677 < 0.17). `max-train-validation-gap-t-stat: 2.0`으로 대체했다.

최종 목표(`application.yaml`, 요청으로 변경 불가):

```yaml
min-excess-return: 0.02               # 실용 하한 — 유의해도 2%p 미만은 성과로 부르지 않음
min-excess-t-stat: 2.0                # 유의성 — 노이즈로는 넘을 수 없게
min-slip-count: 100 / min-betting-day-count: 20
max-train-validation-gap-t-stat: 2.0  # 두 구간은 노이즈로 설명되는 범위에서만 어긋나야 함
```

랭킹(`ObjectiveScore`)도 다리 단위 초과수익으로 전환했다. 목표와 다른 기준으로 후보를 고르면
탐색이 목표를 향하지 않는다.

### 재정의 후 첫 전수 탐색 (962후보, `MARKET_EDGE` 480점 전수, seed 42)

**`goalAchieved: false` — 위양성 없음.**

| 알고리즘 | 학습 다리 | 학습 초과 (t) | 검증 다리 | 검증 초과 (t) | 불일치 |
|---|---|---|---|---|---|
| `MARKET_EDGE` (최고) | 930 | −0.8% (−0.18) | 318 | **+25.7%** (3.19) | **2.90σ** ❌ |
| `MARKET_EDGE` 외 3건 | 466~1,260 | −0.3~−1.0% | 146~480 | +15.8~+28.5% | 2.20~2.59σ ❌ |
| `WIN_RATE_ODDS` (최고) | 741 | **+5.1%** (1.16) | 315 | **+11.5%** (1.70) | **0.79σ** ✅ |
| `WIN_RATE_ODDS` 외 3건 | 478~963 | +5.0~+5.6% | 170~381 | +2.7~+20.1% | 0.40~1.38σ ✅ |

세 가지를 읽을 수 있다.

- **`MARKET_EDGE`는 창(window) 효과다.** 학습 구간 초과수익이 t = −0.07~−0.25, 즉 **정밀하게 0**인데
  (표본이 1,000다리 내외라 ±4%p로 좁다) 검증에서만 +16~29%가 나온다. 파라미터를 어떻게 잡아도
  같은 패턴이므로 파라미터가 아니라 **구간이 특이했다.**
- **`FAVORITE`는 두 구간 모두 음수다.** 시장 추종이 무기술보다 나쁘다 — 인기팀 편향
  (favorite–longshot bias)이 예상대로 나타났다. 측정 장치가 옳게 작동한다는 **좋은 검증**이기도
  하다: 정보 없는 기준선은 0 이하여야 하고, 실제로 그렇다.
- **`WIN_RATE_ODDS`만 두 구간 모두 양수다.** 모든 설정에서 학습이 +5%대로 거의 일정하고 검증도
  양수, 불일치 0.4~1.4σ. 합산 추정 **+7.0%p/다리, t ≈ 1.90**(1,056다리). **유의성 미달이지만,
  이 프로젝트에서 처음으로 노이즈가 아니라 신호처럼 보이는 결과다** — 부호와 크기가 두 구간에서
  일치하기 때문이다.

### 판정

- 목표 미달. 루프는 계속된다.
- **가장 유망한 단서: B 계열(폼 필터)의 `WIN_RATE_ODDS`.** §11까지 "부결"로 적은 것은 절대 수익률
  기준이었기 때문이다. 초과수익으로 보면 이 계열만 일관되게 양수다.
- 다음 이터레이션의 우선순위는 **새 계열 추가가 아니라 `WIN_RATE_ODDS`의 표본 확대**다. t는 표본의
  제곱근에 비례하므로, 같은 +7%p 엣지라도 다리를 1,056 → 2,300개로 늘리면 t ≈ 2.8이 되어 판정이
  가능해진다. 필터 완화(`x` 하향, `y` 상향)나 기간 확대가 그 수단이다.
- 주의: 이 +7%p는 파라미터를 학습 구간에서 고른 뒤의 값이라 낙관 편향이 있다. 표본을 늘린 뒤
  **새 홀드아웃**에서 재확인해야 한다.

## 13. 베팅 시장 교체 — `야구 승패`(2면) 도입 (2026-08-17)

### 문제: `1`은 무승부가 아니라 1점차 경기다

`FAVORITE_MARTINGALE`의 슬립 적중률이 20%에 그쳤다. 원인은 알고리즘이 아니라 **시장 선택**이었다.
`야구 승1패`의 `TOTAL_RESULT`는 `승` = 홈 2점차 이상, `1` = **1점차 경기**, `패` = 원정 2점차 이상이다
(§6에서 이미 확인된 사실이지만, 그것이 적중률의 상한을 정한다는 점은 여기서 처음 결론으로 쓰였다).
시장 내재확률로 `1` 구간이 22~28%를 차지하므로 **우세팀 픽은 1점차 경기를 전부 잃는다.**

배당을 낮춰 적중률을 올리는 길은 막혀 있다. 발표배당 2,611건 중 어느 한 면이라도 1.50 미만인 경기는
10건(0.38%), 최저가는 1.36이다. 재고 자체가 없다.

`야구 승패`에는 이 중간 구간이 없다. **같은 팀을 그대로 픽하되 1점차 승리가 적중이 된다.**

### 2면 오버라운드 실측 = 1.13629 (상수)

사용자가 제공한 와이즈토토 `야구 승패` 발표배당 24경기(2026-08-14~15, MLB 15 / NPB 6 / KBO 3)에서
`1/승 + 1/패`를 계산했다.

| | 값 |
|---|---|
| 평균 | **1.13629** |
| 범위 | 1.13516 ~ 1.13769 |
| 표준편차 | ≈ 0.0007 |

리그·배당대와 무관하게 상수다(1.21/3.23 → 1.1360, 2.56/1.34 → 1.1369). 3면의 1.15와 같은 성격의
고정 하우스 마진이다. 무기술 레그 기대수익은 `1/O − 1`이므로 **3면 −13.19% → 2면 −11.99%**,
시장을 바꾸는 것만으로 +1.2%p가 붙는다.

`BaseballResultDivBackfillService`가 실현 배당에서 역산해 쓰던 1.14는 약 0.4% 높았고, 실측값으로 교체했다.

### 유추 공식과 그 검증

`야구 승패` 행에는 `PUB_*`가 없다. 이긴 쪽 `TOTAL_DIV`만 있고, 그것을 선택·사이징에 쓰면 D2 그대로다.
그래서 **같은 경기의 3면 발표배당에서 2면 가격을 유도**한다 — 입력이 전부 경기 전 공표값이므로 누수가
구조적으로 없다.

```
p2_home = impliedHome + s · impliedDraw          (s = 1점차 경기 중 홈 승리 비율)
p2_away = impliedAway + (1 − s) · impliedDraw
odds2   = 1 / (p2 × 1.13629)                     (2자리 반올림)
```

`GET /api/research/two-way-odds-check`로 실현면 `TOTAL_DIV`(= 이긴 쪽의 실제 발표가)와 대조해 검증했다.
2,369경기 중 2,349건(99.2%)이 승패 행과 매칭됐고, 그중 2,332건을 비교했다.

| `s` | 평균 절대오차 | 승 실현 편향 | 패 실현 편향 |
|---|---|---|---|
| 0.50 | 5.17% | +5.59% | −4.65% |
| 0.55 | 2.70% | +2.77% | −2.00% |
| **0.60** | **1.60%** | **+0.10%** | **+0.79%** |
| 0.65 | 3.17% | −2.43% | +3.77% |
| 0.70 | 5.83% | −4.85% | +6.91% |

**두 면의 편향이 동시에 0을 지나는 지점이 0.60이다.** 즉 홈팀이 1점차 경기의 약 60%를 이긴다 —
홈 어드밴티지가 접전에 몰려 있다는 뜻이다. 코인플립 가정 0.5는 측정 가능하게 틀렸다.

중요한 구분: 이 보정의 대상은 **결과가 아니라 발표가격**이다. 결과는 식에 들어가지 않는다. 다만 관측
가능한 것이 이긴 쪽 가격뿐이라 표본이 결과에 조건화되어 있으므로, `oneRunHomeShare`는 상수로 박지 않고
**스윕 파라미터로 남겨 학습 구간 초과수익으로 고른다.** 이 측정은 스윕 범위의 중심만 정한다.

버킷별 캘리브레이션(예측 대 실측)은 의미 있는 표본 구간 전부에서 ±2.6%p 이내였다 — 추정기는
편향되지 않았고, 동시에 **시장은 효율적이다**(어느 배당대에서도 실측이 내재확률을 유의하게 넘지 않는다).

### 탐색 결과 (260421~260815, train 260421~260711 / validation 260712~260815, seed 42, 120후보 전수)

검증 구간 수치. 같은 경기·같은 픽·같은 정산 코드다.

| 알고리즘 | 조합 | 적중 | **적중률** | 레그 초과수익(검증) | (학습) |
|---|---|---|---|---|---|
| `FAVORITE` (combinedN=2) | 333 | 49 | 0.1471 | −0.0618 | −0.0119 |
| **`FAVORITE_2WAY`** (combinedN=2, s=0.60) | 330 | 112 | **0.3394** | +0.0006 | +0.0078 |
| `FAVORITE` (combinedN=3) | 215 | 18 | 0.0837 | −0.0547 | −0.0180 |

레그 단위 적중률은 같은 경기에서 **41.4% → 56.4%**다.

두 가지가 눈에 띈다.

1. **적중률은 목표대로 올랐다.** 2게임 조합 기준 0.147 → 0.339 (2.3배), 마틴게일 0.170 → 0.305 (1.8배).
   `0.564² = 0.318`이라는 산술과 일치하고, 짧은 배당부터 고르므로 그보다 높게 나온다.
2. **레그 초과수익이 세 쌍 모두에서 약 +6.2%p 개선됐다** (−0.0618→+0.0006, −0.0547→+0.0064,
   −0.0776→−0.0163). 서로 독립인 세 비교에서 같은 크기로 나온 것은 우연이 아니라 구조적이라는 뜻이다.
   그중 +1.2%p는 마진 차이로 설명되고, 나머지 ~5%p는 favorite–longshot bias가 2면에서 덜 작동한다는
   해석이 가능하다 — 다만 아래 판정을 볼 것.

### 판정 — 미달 (`goalAchieved: false`)

최고 후보 `FAVORITE_2WAY (combinedN=3, s=0.65)`의 검증 초과수익은 **+0.76%p, t = 0.25**다.
요구치는 +2%p이고 t ≥ 2.0이므로 **양쪽 다 미달**이다. 위 2번의 "+6.2%p 개선"은 기준선 대비 상대적
개선이지 절대적으로 유의한 초과수익이 아니다. §10·§12에서 세 번 반복된 위양성이 정확히 이 지점 —
"좋아 보이는 상대 비교"를 절대 판정으로 바꿔 읽는 것 — 에서 나왔으므로 여기서 멈춘다.

**즉 이번 변경의 확정된 성과는 적중률과 시장 마진이지, 수익성이 아니다.**

### 예상과 어긋난 것: 최대 낙폭은 오히려 커졌다

사전 예측은 "적중률이 오르니 시퀀스 한도소진이 줄어 낙폭도 준다"였다. 실측은 반대였다:
`FAVORITE_2WAY_MARTINGALE` 131,771~164,103원 대 `FAVORITE_MARTINGALE` 61,110~88,928원.

이유는 마틴게일의 배수가 `O/(O−1)`이기 때문이다. 조합배당이 3.0에서 2.3으로 내려가면 배수가
1.50 → 1.77로 **커진다**. 시퀀스당 한도소진 확률은 낮아지지만(10단계 필요 → 7단계 필요), 시퀀스가
그만큼 빨리 끝나 같은 기간에 더 많은 시퀀스를 돌게 되므로 **단위 기간당 소진 횟수는 비슷해지고
각 단계의 배팅금만 커진다.** 59슬롯은 이 지표를 논하기엔 작은 표본이지만, "적중률이 오르면 낙폭이
준다"는 추론이 마틴게일에서는 성립하지 않는다는 점은 분명하다.

### 계열 현황 갱신

시장 교체는 **새 신호 계열이 아니다**(taxonomy A + F). `s = 0.5`에서 2면 우세팀은 항상 3면 우세팀과
같으므로, 픽 대상은 바뀌지 않고 정산 시장만 바뀐다(보정값 0.60에서는 근소한 원정 우세 경기가 홈으로
뒤집힐 수 있다 — 2면 시장이 실제로 홈에 더 유리하므로 옳은 거동이다).

따라서 §12의 우선순위는 유지된다: 다음은 **`WIN_RATE_ODDS`의 승패 버전**이다. 두 구간 모두 초과수익이
양수인 유일한 계열이고, 이제 그 위에 +6%p짜리 시장 교체 이득을 얹을 수 있는 배관이 있다.
